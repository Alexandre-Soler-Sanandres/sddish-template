# STATUS-TRANSITIONS Rules

## Rules

| ID | Type | Rule |
| --- | --- | --- |
| STT-01-010 | Transition | When a significant change lands on a Use Case or Spec already at `ready` or later, MUST reset that artifact to `draft`, recursively reset every child derived from it the same way, leave Implementation Plans unchanged, and stop for user instruction after the reset. |
| STT-01-020 | Transition | Implementing MUST set a Task or Plan to `in-progress` when work starts and to `done` when work completes; when that completion leaves every child derived from a Spec or Use Case at `done`, the parent artifact also becomes `done`. |
| STT-01-030 | Transition | An explicitly user-approved Plan promotion MAY set the Plan to `ready` only when its own readiness and parallel-work gates pass (`IPL-02-010`-`012`, `IPL-05-010`/`011`) and the upward walk succeeds, and in that same walk set each included Task, Spec, and Use Case to `ready` only when its artifact-local promotion gates pass fresh against current content (`TSK-02-010`-`012`, `TSK-06-010`-`040`; `SPS-02-010`-`012`, `SPS-05-011`, `SPS-08-010`-`030`; `UCS-03-010`-`012`, `UCS-05-015`, `UCS-07-010`-`030`) and, for Spec or Use Case, every child in that funnel is already `ready`; any failure aborts the whole walk with no status changes anywhere, the walk stops at Use Case, a risk-tier skip path truncates it at the chain's real end, and promotion by this rule does not itself count as a significant change for `STT-01-010`. |
| STT-01-040 | Transition | An explicit operator instruction naming a specific Task, Spec, or Use Case MAY set only that artifact to `ready` when its own artifact-local promotion gates pass fresh against current content (`TSK-02-010`-`012`, `TSK-06-010`-`040`; `SPS-02-010`-`012`, `SPS-05-011`, `SPS-08-010`-`030`; `UCS-03-010`-`012`, `UCS-05-015`, `UCS-07-010`-`030`); child fan-out is not required on this path, `STT-01-030` and `STT-01-040` are the only paths by which a Task, Spec, or Use Case reaches `ready`, and a Plan has no separate manual-instruction row because `STT-01-030` is already that manual gate for the Plan itself. |
| STT-01-050 | Transition | When an Idea is promoted into a next-tier artifact or incorporated as an in-place amendment to an existing Use Case or Spec, MUST close the Idea by setting `status` to `landed`, populating `next` with the citing artifact ID, and moving it to `archive/`; this does not wait for the citing artifact to reach `done`. |
| STT-02-010 | Reconsideration | Whenever an artifact in the Idea -> Use Case -> Spec -> Task -> Plan chain moves off a status that `STT-01-010`, `STT-01-020`, `STT-01-030`, `STT-01-040`, or `STT-01-050` set, for a reason other than another `STT-01-*` rule already having set it again, MUST reconsider every other artifact in the chain, in either direction, whose own status depended on that fact. |
| STT-02-011 | Reconsideration | MUST report the outcome of `STT-02-010` explicitly, including when the result is `no change needed`. |
